# strategy-discovery-m2 — Brief

## Goal

Execute Milestone 2 of `implementation-artifacts/strategy-discovery-project-plan.md` (= `docs/plan.md` Phase 8, lines 191-208 at commit `39ec658829bb8ec0c430a856b9ac03b4ae747719`; `docs/plan.md` is never edited, so those lines are stable): turn an annotated corpus into a canonicalized per-position feature dataset, induce an ordered decision list from it, emit it as a self-contained human-readable `HeuristicStrategy`, execute it through `RuleInterpreter::choose` so `heuristic-rules` strategies play in the match engine and the Milestone 1 harness, validate and archive every emitted heuristic with reproducing provenance, and chain everything behind a `discover` subcommand whose repeat runs are byte-identical.

### D2. `Featurizer<G>` — one game-neutral way to turn a state into its feature environment

- `src/core/featurizer.rs`: `pub struct Featurizer<G: GameDomain> { rules: Arc<dyn GameRules<G>>, primitives: Arc<dyn GamePrimitives<G>>, canonicalizer: Option<Arc<dyn Canonicalize<G>>>, players: Vec<G::Player> /* turn order */, extractors: Vec<Arc<dyn FeatureExtractor<G>>> /* [tier-1 PrimitiveFeatures, then the supplied extractor if any] */, vocabulary: FeatureVocabulary }`.
- `Featurizer::new(rules, primitives, canonicalizer, players, supplied: Option<Arc<dyn FeatureExtractor<G>>>) -> Result<Self, FeatureError>` builds `PrimitiveFeatures::new(rules.clone(), primitives.clone())` itself (tier-1 is always mechanical, never listed by the game) and pushes, in order: `FeatureDef::native("side_to_move", Tier::Primitive, "index of the player to move in turn order (0 = first player)")`, then every definition of every extractor (`FeatureError::Duplicate` on a name clash). Requires blanket impls added to `src/core/traits.rs`: `impl<G: GameDomain, T: GameRules<G> + ?Sized> GameRules<G> for Arc<T>` and the same for `GamePrimitives<G>` (pure delegation), so `PrimitiveFeatures<G, Arc<dyn GameRules<G>>, Arc<dyn GamePrimitives<G>>>` type-checks.
- Methods: `vocabulary(&self) -> &FeatureVocabulary`; `rules()`, `primitives()`, `players()`; `position_count()`; `side_to_move(&self, state) -> Option<usize>` (slot in `players`); `canonical_frame(&self, state) -> (G::State, Permutation)` (`canonicalize_with_transform`, or `(state.clone(), Permutation::identity(position_count))` without a canonicalizer); `extract(&self, state) -> FeatureVector` (NO canonicalization: `side_to_move` as `Int` — `-1` when the mover is not in `players` — merged with every extractor's `extract(state)`, later extractors win on clash); `extract_canonical(&self, state) -> (FeatureVector, Permutation)` = `extract` on the canonical frame; `action_positions(&self, legal: &[G::Action], perm: &Permutation) -> Option<Vec<usize>>` (canonical-frame position of every action via `primitives.action_position` then `perm.apply`; `None` if any action has no position).
- `GameBundle<G>` gains `pub supplied_features: Option<Arc<dyn FeatureExtractor<G>>>` (tier-2, game-supplied; tic-tac-toe: `Some(Arc::new(TicTacToeFeatures))`) and `pub fn featurizer(&self, include_supplied: bool) -> Result<Featurizer<G>, CorpusError>` (`primitives == None` → `CorpusError::Precondition("game `{name}` declares no primitives; feature extraction, heuristic-rules play and mining are unavailable")`; `FeatureError` → `CorpusError::Config`). `include_supplied = false` is the Milestone 3 "withhold tier-2" switch; this milestone always passes `true` except in tests.
- `EngineBundle<G>` gains `pub featurizer: Option<Arc<Featurizer<G>>>` (update its manual `Clone`, both literal sites: `GameBundle::engine_bundle` fills `self.featurizer(true).ok().map(Arc::new)`; `src/games/tictactoe/mod.rs::engine_bundle()` builds `Featurizer::new(Arc::new(TicTacToeRules), Arc::new(TicTacToePrimitives), Some(Arc::new(TicTacToeCanonicalizer::new())), vec![Player::X, Player::O], Some(Arc::new(TicTacToeFeatures)))`).
- Tic-tac-toe vocabulary order (asserted in a `corpus.rs` test): `side_to_move`, the 47 tier-1 names in `PrimitiveFeatures::definitions()` order, the 22 `ttt.*` names → 70 definitions, no duplicates.

### D3. `RuleInterpreter::choose` (recorded in ADR 0016)

- `RuleInterpreter<G> { heuristic: HeuristicStrategy, ordered: Vec<Rule> /* heuristic.ordered_rules() cloned once */, featurizer: Arc<Featurizer<G>>, seed: u64, rng: ChaCha8Rng /* seed_from_u64(seed) at construction */ }`; `RuleInterpreter::new(heuristic, featurizer, seed) -> Result<Self, DslError>`; `RuleInterpreterProvider::new(heuristic, featurizer) -> Result<Self, DslError>` validates `heuristic.validate()` AND that every native definition (`expr == None`) in `heuristic.definitions` is a name in `featurizer.vocabulary()`, else the new variant `DslError::UnavailableFeatures(Vec<String>)` (`#[error("native features not produced by this game: {0:?}")]`). `create(seed)` clones the heuristic and featurizer `Arc`. `heuristic()`, `seed()` accessors stay.
- `build_heuristic_rules` in `src/strategy/registry.rs`: `bundle.featurizer.clone().ok_or_else(|| StrategyError::Other("strategy `heuristic-rules` requires a feature context (game primitives); this game provides none"))`, then the provider (`DslError` → `StrategyError::Other(e.to_string())`). `StrategyError::Unimplemented` is no longer produced for `heuristic-rules`.
- `choose(state, legal)`: (1) `legal.is_empty()` → `NoLegalActions`. (2) `(canonical, perm) = featurizer.canonical_frame(state)`; `native = featurizer.extract(&canonical)`; `env = heuristic.definitions.evaluate(&native)` (`FeatureError` → `StrategyError::Other(format!("evaluating features: {e}"))`). Conditions and selectors are evaluated in the CANONICAL frame; set-valued targets are mapped back through `perm.inverse()`. (3) For each rule in `ordered` order: `fired = rule.condition.evaluate(&env)?.as_bool()?`; if fired, run the selector; a selector that yields no candidate (empty `TargetIn` intersection, or `Maximize`/`TargetIn` over actions without positions) does NOT fire the rule — continue to the next rule. (4) No rule fired → the fallback selector; if it yields nothing → uniform seeded choice over `legal` (the `AnyLegal` path). Every returned action is an element of `legal`.
- Selectors: `AnyLegal` → `legal` itself. `TargetIn { expr }` → `targets = expr.evaluate(&env)?.as_set()?`; candidates = every `a` in `legal` (in `legal` order) with `primitives.action_position(a).map(|p| perm.apply(p))` ∈ `targets` (equivalently a raw position in `perm.inverse()` of the set). `Maximize { expr }` → for each `a` in `legal`: `next = rules.apply(state, a)?` (`RulesError` → `StrategyError::Other`), `(cn, _) = canonical_frame(&next)`, `v = expr.evaluate(&definitions.evaluate(&featurizer.extract(&cn))?)?` as f64 (`Int` → as f64, `Float`, anything else → `StrategyError::Other("maximize expression must be numeric")`); candidates = all `a` whose `v` equals the maximum under `f64::total_cmp` (note features are computed relative to the player to move in `next`, i.e. the opponent — document this in ADR 0016 and the README).
- Tie-break: exactly one candidate → return it without touching the RNG; otherwise `candidates.choose(&mut self.rng)` (`rand::seq::IndexedRandom`), mirroring `MinimaxStrategy` (ADR 0008). Same seed + same sequence of positions ⇒ same moves; serial == parallel.
- Tests (Phase 1): `tests/interpreter_tactics.rs` — a hand-written heuristic over `ttt.winning_cells` / `ttt.blocking_cells` with a derived definition (e.g. `has_win = (count(ttt.winning_cells) > 0)`, tier-3) (a) takes the immediate win in a position with a winning cell, (b) blocks the opponent's threat when no win exists, (c) a `Maximize { count(free) }`-style selector and an `AnyLegal` fallback are deterministic across two interpreters with the same seed and differ for some seed pair, (d) the heuristic plays complete games through `RayonMatchEngine` against `random` and `perfect` with no error (`Ok` records, no `Unimplemented`), (e) a rule that references a native feature the game does not produce fails at provider construction with `UnavailableFeatures`, (f) a canonical-frame check: a position and its rotated image yield symmetric choices (the chosen cell of the rotated position is the rotation of the chosen cell, given equal seeds and a single-candidate rule). `tests/match_engine.rs` and `tests/cli_evaluate.rs` are rewritten to assert that `heuristic-rules` now builds and plays (`strategies-heuristic.toml` → exit 0, a `strategy=empty kind=heuristic-rules` line; losses may be > 0). Unit tests in `interpreter.rs` use a toy game with a trivial `GamePrimitives` (copy the ring game in `derived.rs` tests).

### D5. Miner (`src/discovery/tree.rs`, `src/discovery/mine.rs`; recorded in ADR 0015)

- `MineParams` (in `src/io/schema.rs`; Serialize/Deserialize/Clone/Debug/PartialEq; every field `#[serde(default = ...)]`): `engine: String` (default `"cart"`; allowed `"cart"`, `"linfa-trees"`), `depths: Vec<usize>` (default `[8]`; one candidate per entry; `0` = unlimited), `min_leaf: usize` (default `1`), `seed: u64` (default `0`), `holdout_fraction: f64` (default `0.0`). `validate()` → `CorpusError::Config` on unknown engine, empty/duplicate depths, `min_leaf == 0`, `holdout_fraction` outside `[0, 1)`.
- Train/holdout split: `holdout_fraction == 0.0` → every row trains, no holdout; otherwise row indices shuffled with `ChaCha8Rng::seed_from_u64(seed)` (`rand::seq::SliceRandom::shuffle`), the last `floor(rows * fraction)` are held out. The emitted heuristic is trained on the train split only.
- Engine `cart` (`tree.rs`, pure integer arithmetic, no dependency on linfa): `pub struct Tree { root: Node }`, `Node::{Leaf { class: usize, rows: Vec<usize> }, Split { column: usize, threshold: f64 /* a data value present at the node */, left: Box<Node> /* rows with x <= threshold */, right: Box<Node>, rows: Vec<usize> }}`; `pub fn fit(matrix: &[Vec<f64>], labels: &[usize], n_classes: usize, max_depth: usize /* 0 = unlimited */, min_leaf: usize) -> Tree`. Candidate splits at a node: for each column in column order, every distinct value `v` among the node's rows except the largest (`left = x <= v`); both children must hold ≥ `min_leaf` rows. Score = exact Gini gain compared as rationals: maximize `S = Σ_{child} (Σ_k n_{child,k}²) / n_child` over the two children, comparing two candidates via cross-multiplication in `u128`; a split is applied only if `S` strictly exceeds the parent's `Σ_k n_k² / n` (no gain → leaf). Ties → the first candidate in (column index, threshold ascending) order. Stop at `max_depth`, on a pure node, or when no candidate qualifies. Deterministic by construction on every platform.
- Leaf labeling (both engines; soundness-driven): a leaf's class = the class `c` (vocabulary order; `none` excluded) maximizing the number of leaf rows whose `qualifying` list contains `c`; ties → lowest class index; maximum 0 → `none`. The split search uses the single `label` column (Gini over `label` indices, `none` being its own class); only the final leaf label uses `qualifying`.
- Engine `linfa-trees` (`mine.rs`, behind the `linfa`, `linfa-trees`, `ndarray` dependencies): `linfa::Dataset::new(Array2<f64>, Array1<usize>).with_feature_names(columns)`; `DecisionTree::params().max_depth(if d == 0 { None } else { Some(d) }).min_weight_leaf(min_leaf as f32).min_weight_split((2 * min_leaf) as f32).fit(&dataset)`; the fitted tree is converted into the same `Tree` shape by walking `root_node()` / `children()` / `split()` (left = `x <= split_value` where `split_value` is a midpoint; the emitted DSL threshold is `floor(split_value)` for `int`/`set`/`bool` columns and the raw midpoint with `Lt`/`Ge` for `float` columns) and routing the train rows through the converted tree with the `<=` predicate; leaves are then relabeled by the soundness rule above (linfa's `prediction()` is discarded). Documented as NOT byte-stable across runs when split scores tie (see Pinned facts); `discover` determinism evidence uses `cart`.
- Tree → decision list (`mine.rs`): leaves in depth-first order (left before right), leaf ordinal `k` (1-based among ALL leaves): a leaf whose class is `none` emits no rule (its rows fall to the fallback and are counted as `fallback_rows`); otherwise `Rule::new(format!("rule{k}"), (leaves - k) as i32, condition, ActionSelector::TargetIn { expr: FeatureExpr::named(class) })` where `condition = FeatureExpr::all(path_predicates)` (root leaf → `all(vec![])` which evaluates to `true`). Path predicate for a split on column `c` with threshold `v`: kind `int` → left `Cmp(Le, Ref c, Int v)`, right `Cmp(Gt, Ref c, Int v)`; kind `set` → the same over `Count(Ref c)`; kind `bool` → left `Not(Ref c)`, right `Ref c`; kind `float` → `Cmp(Le|Gt, Ref c, Float v)` for `cart`, `Cmp(Lt|Ge, Ref c, Float midpoint)` for `linfa-trees`. `heuristic = HeuristicStrategy::new(name)` with `fallback = AnyLegal`, `definitions` = `featurizer.vocabulary().closure(&heuristic.references())` pushed in order (self-containment; `validate()` must pass — asserted by the miner before returning, `GeneratorError::Failed` otherwise).
- Evidence: `RuleEvidence { rule: String, class: String, support: usize /* train rows reaching the leaf */, sound: usize /* rows whose qualifying contains class */, soundness: f64 /* sound/support */, label_matches: usize, occurrences: usize /* Σ row.occurrences */, outcomes: OutcomeTally { win: usize, draw: usize, loss: usize } /* by row.value from the mover's perspective */ }`; `MinedHeuristic { name: String /* "mined-d{depth}-l{min_leaf}" for cart, "mined-linfa-d{depth}-l{min_leaf}" for linfa-trees */, engine: String, max_depth: usize, min_leaf: usize, heuristic: HeuristicStrategy, rules: usize, leaves: usize, depth: usize, train_rows: usize, holdout_rows: usize, train_accuracy: f64 /* predicted class == label */, train_soundness: f64 /* predicted class qualifies; none never qualifies */, holdout_accuracy: Option<f64>, holdout_soundness: Option<f64>, fallback_rows: usize, evidence: Vec<RuleEvidence> /* rule order */ }`; `MiningReport { schema_version, game, run_id: Option<String>, params: MineParams, dataset: DatasetManifest, candidates: Vec<MinedHeuristic> /* depths order */ }`.
- `Miner<G> { featurizer: Arc<Featurizer<G>>, params: MineParams }` implements `StrategyGenerator<G>` with `Input = Dataset<G>`, `Candidate = MinedHeuristic`; `generate(&mut self, dataset, seed)` uses `seed` for the holdout split (overriding `params.seed`) and returns one candidate per depth. `MineAnalyzer` (`name() = "mine"`, `requires_annotations() = true`) builds the dataset exactly as `DatasetAnalyzer` does (never reads `dataset.jsonl`), runs the miner with `options.mine` (D6), and returns `AnalyzerOutput::new(HEURISTICS_FILE, &MiningReport, true)`. `render` → `## Mine` (overview table: engine, rows, classes, candidates), then per candidate `### {name}` (metric table: max_depth, min_leaf, rules, leaves, depth, train_accuracy, train_soundness, holdout_accuracy or `none`, fallback_rows), `#### Rules` as an ordered list — one line per rule `{k}. if {rule.condition} then {rule.action} — support {support}, sound {sound} ({soundness:.3}), outcomes W/D/L {win}/{draw}/{loss}` in firing order followed by a final line `otherwise: {fallback}` — and `#### Feature definitions` as a bullet list of `` `{def}` `` Display strings. Markdown rules apply (blank line after every heading, around lists/tables; floats `{:.3}`).
- Tests (Phase 2): `tree.rs` unit tests on a hand-built 2-column toy matrix with known best split, tie-break (two equally good columns → the lower index), `min_leaf` enforcement, pure-node stop, `max_depth` 0/1, and `fit` called twice → identical structure; `mine.rs` unit tests: a 3-leaf toy tree converts to two rules + one fallback with the exact `FeatureExpr` shapes above, names `rule1..`, priorities descending; `linfa-trees` engine on the same toy data (tie-free) yields the same rules as `cart`; `tests/mine.rs` (integration): exhaustive annotation → dataset → `cart` depth 8 heuristic validates, has ≥ 1 rule, `train_soundness ≥ 0.9`, mining twice gives identical `MiningReport` JSON; bounded to one exhaustive fit per engine (≤ 5 s debug together). `tests/mining_bench.rs`: non-failing `[bench]` lines — dataset build ms, fit ms per engine at depths 4/8/0, rules/leaves/soundness per candidate.

## Assumptions

- `linfa` 0.8.1, `linfa-trees` 0.8.1, `ndarray` 0.16.1 build on stable 1.94.1 / edition 2024 on Windows and Ubuntu without BLAS features (the spike built them on this machine; CI Ubuntu builds are assumed equivalent).
