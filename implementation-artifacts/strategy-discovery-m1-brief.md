## Decisions (the Milestone 1 design — fixed here so the decomposer projects, not invents)

### D1. Module layout and game neutrality

- New library modules: `src/discovery/tournament.rs` (roster play + per-opponent tallies), `src/discovery/evaluate.rs` (strategy-side agreement, behavior signature, evaluation report assembly, strict check), `src/discovery/archive.rs` (archive + novelty). All three are generic over `G: EngineGame + CorpusGame`, take a `&GameBundle<G>`, and name no game. Re-exported from `src/discovery/mod.rs` (one step per phase edits `mod.rs`).
- New CLI module `src/cli/evaluate.rs` + `Command::Evaluate(evaluate::EvaluateArgs)` in `src/cli/mod.rs`; game resolution via the existing `dispatch_game!` only. `src/cli/games.rs` is unchanged (it already dispatches any subcommand); it stays the only non-test `.rs` outside `src/games/` naming a concrete game.
- New record types are NON-generic (names, counts, rates, `StrategySpec`, `serde_json::Value` for action signatures) and live in `src/io/schema.rs` next to the existing records, so `tournament.rs`, `evaluate.rs`, `archive.rs` can be written in parallel against them. New file-name consts in `src/io/schema.rs` and re-exported from `src/io/mod.rs`: `EVALUATION_FILE = "evaluation.json"`, `ARCHIVE_FILE = "archive.json"`, `ARCHIVE_ENTRIES_FILE = "entries.jsonl"` (+ the `ANALYZE_FILE` re-export). Every new document carries `schema_version: SCHEMA_VERSION` (1). No existing record, const, seed formula, `config_hash`, CLI line or pin changes.

### D2. `GameBundle` gains the benchmark roster

- Add `pub roster: Roster` to `GameBundle<G>` (the versioned benchmark population; its `id()` is the provenance `roster_id`). `default_strategies` stays as-is (other commands use it). Tic-tac-toe: `roster: benchmark_roster()`, `default_strategies: benchmark_roster().entries` — `roster.entries == default_strategies` asserted in `src/games/tictactoe/corpus.rs` tests. Only `src/games/tictactoe/corpus.rs` constructs a `GameBundle`.
- The harness takes its opponents from `bundle.roster` unless the caller passes an explicit `Roster` (CLI `--roster FILE`, a TOML `Roster` document: `name`, `version`, `[[entries]]` with `name` + `[entries.spec]`; validated with `Roster::validate()`; tests use tiny rosters to stay inside the budget).

### D3. Tournament harness (`src/discovery/tournament.rs`)

- Input: `bundle`, `registry: &StrategyRegistry<G>` (built from `bundle.engine_bundle(evaluator)`), `under_test: &RosterEntry`, `roster: &Roster`, `TournamentConfig { games_per_pairing: usize, seed: u64, max_plies: Option<usize>, reference: String, threads: Option<usize>, serial: bool }`.
- Pairings: for every roster entry in roster order (`opponent_index`) and every seat `seat in 0..bundle.players.len()` (tic-tac-toe: seat 0 = X, seat 1 = O — "both colors"; N-player games get N seatings): the strategy under test occupies `bundle.players[seat]`, the opponent every other seat. `pairing_index = opponent_index * seats + seat`; batch seed = `cell_seed(config.seed, pairing_index)` (reuse, do not invent); one `MatchEngine::run(&MatchConfig { games: games_per_pairing, seed: batch_seed, max_plies }, players)` per pairing through `RayonMatchEngine::{serial, with_threads, new}` chosen by `serial`/`threads` (outputs never depend on the choice). The under-test entry may coincide with a roster entry (evaluating `perfect` from the roster is legal: it plays a clone of itself).
- Classification per game from `MatchRecord.outcome` with `G::winner`: `Some(p)` and `p == bundle.players[seat]` → win; `Some(_)` → loss; `None` winner → draw; `outcome: None` (max_plies abort) → unfinished. Unfinished is never a loss. Rates = count / games (exactly `0.0` when games = 0).
- Errors: any `MatchError` (including `Strategy(Unimplemented)` from a `heuristic-rules` under-test or opponent) aborts the tournament with `Err(CorpusError::Match(..))` — never tallied as a loss.
- Output types (in `src/io/schema.rs`; all Serialize/Deserialize/Clone/Debug/PartialEq; Vecs in roster/seat order, never HashMap): `PairingResult { opponent: String, seat: usize, player: String /* format!("{:?}", bundle.players[seat]) */, games, wins, draws, losses, unfinished: usize, win_rate, draw_rate, loss_rate: f64 }`; `OpponentResult { opponent: String, games, wins, draws, losses, unfinished, win_rate, draw_rate, loss_rate, by_seat: Vec<PairingResult> }`; `TournamentResult { roster_id: String, reference: String, games_per_pairing: usize, seed: u64, opponents: Vec<OpponentResult>, totals: OpponentResult-like counts without `opponent` (use a `Tally { games, wins, draws, losses, unfinished, win_rate, draw_rate, loss_rate }` struct shared by all three) }`.
- `reference` = the roster entry the headline loss rate is measured against: CLI `--reference NAME`, default = the LAST roster entry name (graded rosters end in `perfect`); must be a roster entry name else `CorpusError::Config`.

### D4. Strategy-side agreement and behavior signature (`src/discovery/evaluate.rs`)

- Input: annotation records from `--annotations DIR` (a directory holding `annotations.jsonl` + `annotate.json`: a corpus run dir after `annotate --corpus`, or an `annotate --exhaustive --out DIR` dir). Read with `read_jsonl::<AnnRec<G>>` + `check_schema_version` per record; `annotate.json` read as `AnnotateMetadata` for provenance (`mode`, `run_id`, `annotated`). Missing dir/file → `CorpusError::Precondition("{path} not found; run `annotate --exhaustive --game {game} --out {dir}` or `annotate --corpus {dir}` first")`.
- Agreement: for every record with `terminal == false`, in file order with `index` = 0-based position in the file (terminal records count toward the index but are skipped), `legal = bundle.rules.legal_actions(&record.state)`; a FRESH strategy instance `provider.create(game_seed(splitmix64(config.seed ^ AGREEMENT_SEED_SALT), index))` with `pub const AGREEMENT_SEED_SALT: u64 = 0x9E3779B97F4A7C15`; `chosen = strategy.choose(&record.state, &legal)?`; agrees iff `record.optimal_actions.contains(&chosen)`. Positions are processed with rayon (`into_par_iter` over indices, collected in index order); any `StrategyError` aborts (→ `CorpusError::Strategy`). Result `AgreementSummary { positions: usize, agreeing: usize, rate: f64, by_value: BTreeMap<i8, AgreementCounts> /* keyed by record.value: -1, 0, 1 */ }` (reuse `AgreementCounts`).
- Behavior signature (input to novelty, D6): from the same pass, the chosen actions at a fixed deterministic sample of non-terminal records: `n` = number of non-terminal records, `SIGNATURE_SAMPLE: usize = 256`, `stride = max(1, n / 256)`, sampled non-terminal ordinals `0, stride, 2*stride, ...` while fewer than 256 taken and ordinal < n. `BehaviorSignature { sample_id: String /* config_hash of SampleKey { mode: String, run_id: Option<String>, nonterminal: usize, stride: usize } */, actions: Vec<serde_json::Value> /* serde_json::to_value(chosen) per sampled position, in sample order */ }`. Stored in the archive entry; `None` when no annotations were supplied.
- `StrategyEvaluation { name: String, kind: String /* spec.kind() */, spec: StrategySpec, spec_hash: String /* config_hash(&spec) */, tournament: TournamentResult, headline: Headline, agreement: Option<AgreementSummary>, signature: Option<BehaviorSignature> }`; `Headline { reference: String, loss_rate_vs_reference: f64, win_rate: f64, draw_rate: f64, loss_rate: f64 /* totals over all pairings */, games: usize, unfinished: usize, agreement_rate: Option<f64> }`.
- `EvaluationReport` (written to `<out>/evaluation.json` pretty + `\n`): `{ schema_version, evaluation_id: String, game: String, roster: Roster, config: EvaluationConfig { evaluator: String, games_per_pairing: usize, seed: u64, max_plies: Option<usize>, reference: String, annotations: Option<AnnotationSource { mode: String, run_id: Option<String>, records: usize }> }, strategies: Vec<StrategyEvaluation> /* strategies-file order */ }`; `evaluation_id = config_hash(&EvaluationKey { game, roster, config, strategies: Vec<RosterEntry> })`. No paths, timestamps, durations, thread counts, hostnames in any output.
- Strict check (`--strict`, `--max-loss-rate F` default `0.0`): fails when any evaluated strategy has `headline.loss_rate_vs_reference > max_loss_rate`; failure message `reference loss rate exceeded: {name} {:.3} > {:.3}` entries joined by `; ` → `CliError::CheckFailed` → exit 3, AFTER all files and archive entries are written (mirrors `analyze --strict`).

### D5. Strategy archive (`src/discovery/archive.rs`)

- Layout: `<archive>/archive.json` (index, pretty JSON: `ArchiveIndex { schema_version, game: String, entries: Vec<ArchiveIndexEntry { entry_id: String, name: String, kind: String, sequence: usize }> }`) + `<archive>/entries.jsonl` (one `ArchiveEntry` per line, compact JSON, append order = sequence). Non-generic types in `src/io/schema.rs`.
- `ArchiveEntry { schema_version, entry_id: String, sequence: usize, name: String, kind: String, spec: StrategySpec, spec_hash: String, provenance: Provenance { game: String, source: String /* "evaluate" now; "discover" later */, evaluation_id: String, roster_id: String, seed: u64, games_per_pairing: usize, evaluator: String, corpus_run_id: Option<String> /* None in this milestone */, annotations_run_id: Option<String>, annotations_mode: Option<String> }, evaluation: StrategyEvaluation, novelty: Novelty }`.
- `entry_id = config_hash(&EntryKey { game, spec, evaluation_id })`. Append is idempotent: an `entry_id` already present → `Appended::Duplicate` (nothing written), so repeating the same `evaluate` command leaves the archive byte-identical. Different evaluation configs of the same spec create distinct entries (keep all interesting entries — the point is studying the strategy space, not a leaderboard).
- API: `Archive::open(dir, game) -> Result<Archive, CorpusError>` (creates the dir + empty index when absent; existing index with another `game` → `CorpusError::Config`), `append(&mut self, entry_without_novelty..) -> Result<Appended { New(entry_id) | Duplicate(entry_id) }, CorpusError>` computing `sequence` + `novelty` against current entries then rewriting `archive.json` and appending to `entries.jsonl`, `get(entry_id) -> Option<&ArchiveEntry>`, `entries() -> &[ArchiveEntry]` (file order), `len()`, `is_empty()`. Loading an archive and re-serializing its entries reproduces the files byte for byte (round-trip test).

### D6. Novelty metric (recorded in ADR 0012; deterministic, serializable, game-neutral)

- `spec_distance(a: &StrategySpec, b: &StrategySpec) -> f64` in `[0, 1]`: different `kind()` → `1.0`; `Random` vs `Random` → `0.0`; `Minimax`: `max(|da-db| as f64 / max(da,db) as f64, |ea-eb|, if tie_break differs {0.1} else {0.0})`; `HeuristicRules`: Jaccard distance `1 - |A∩B| / |A∪B|` over the sets A, B of canonical rule strings (`serde_json::to_string(rule)` for every rule plus `"fallback:" + to_string(fallback)`), `0.0` when both sets are empty; `Evolutionary`/`Llm` (not constructible) → `0.0` against the same kind.
- `behavior_distance(a: &BehaviorSignature, b: &BehaviorSignature) -> Option<f64>`: `None` unless `sample_id` equal; else fraction of sample positions whose `actions[i]` differ.
- `Novelty { method: String /* "m1-v1" */, nearest_entry_id: Option<String>, nearest_name: Option<String>, spec_distance: f64 /* min over existing entries; 1.0 when archive empty */, behavior_distance: Option<f64> /* min over entries with a comparable signature */, distance: f64 /* behavior_distance.unwrap_or(spec_distance) */, is_novel: bool /* distance > 0.0 */ }`; nearest = the existing entry minimizing `distance` (ties → lowest `sequence`). Floats written with serde_json's default shortest round-trip formatting; rendered text uses `{:.3}`.

### D7. `evaluate` CLI (`src/cli/evaluate.rs`)

- Flags: `--game NAME` (required), `--strategies FILE` (required; `StrategyFile` TOML, every entry evaluated in file order), `--out DIR` (required; receives `evaluation.json`), `--archive DIR` (default `<out>/archive`), `--annotations DIR` (optional; enables agreement + signature), `--roster FILE` (optional override of `bundle.roster`), `--reference NAME` (default last roster entry), `--games N` (default 20), `--seed S` (default 0), `--max-plies M`, `--evaluator NAME` (default bundle default), `--strict`, `--max-loss-rate F` (default 0.0), `--serial`, `--threads N`. Global `-v`/`-q` as every subcommand.
- Flow: resolve bundle via `dispatch_game!` → load strategies file (+ roster override) → build registry from `bundle.engine_bundle(evaluator)` → build EVERY provider (under-test entries and roster entries) before playing anything (build errors → exit per existing mapping) → for each under-test entry: tournament (D3) then agreement/signature (D4) → assemble `EvaluationReport` → write `evaluation.json` → open archive, append one entry per strategy → print stdout → strict check. A runtime error anywhere before the write step writes nothing; `heuristic-rules` entries therefore fail with exit 2 and stderr `error: ... strategy `heuristic-rules` is not implemented: rule interpreter execution lands with heuristic mining (plan.md Phase 8)` (the `anyhow` context names the entry: `evaluating strategy `{name}``).
- stdout (frozen once the decomposer pins the exact format in Phase 3; byte-identical across repeat runs, independent of `-v`, `--serial`, `--threads`): one line per strategy `strategy={name} kind={kind} games={n} wins={w} draws={d} losses={l} unfinished={u} loss_rate_vs_reference={:.3} agreement={:.3 or none} novelty={:.3}` then one final line `evaluation={evaluation_id} game={game} roster={roster_id} reference={name} strategies={n} archive_entries={total entries in archive after this run} out={dir}`. (`archive_entries` is the archive's total, not the number appended, so a repeat run prints the same bytes.)
- Exit codes unchanged: 0 ok; 1 runtime (I/O write, engine failure); 2 usage/input (missing/malformed files, unknown game/evaluator/reference/strategy kind, `Unimplemented` strategy, schema mismatch, archive game mismatch); 3 `--strict` threshold failed.

### D8. Property-based tests (`tests/invariants.rs`, `proptest`)

- Test names contain the invariant phrases (the DoD greps them): `terminal_states_have_no_legal_moves`, `legal_moves_preserve_board_validity`, `canonicalization_is_idempotent`, `canonicalization_preserves_outcome`, `feature_expr_serde_round_trips`, `heuristic_strategy_serde_round_trips`, `strategy_spec_serde_round_trips`. All inside `proptest! { .. }` blocks (the DoD greps `proptest!`).
- Generators: reachable tic-tac-toe states = random play-outs from `TicTacToeRules::initial_state()` driven by a `Vec<u8>` of choice indices (`legal[idx % legal.len()]`, stop at terminal or when the vector ends) — game-neutral in shape, instantiated for tic-tac-toe (tests may name the game). Board validity for tic-tac-toe: `#X == #O` or `#X == #O + 1`, `to_move` consistent with the counts (X when equal), not both players have a completed line, and `legal_actions` = exactly the empty cells unless terminal. Canonicalization via `TicTacToeCanonicalizer::new()` (`canonicalize(canonical) == canonical` with identity transform; `rules.outcome(canonical) == rules.outcome(state)` up to player identity — outcomes are invariant under board symmetries since players are not permuted). `FeatureExpr` arbitrary via `prop_recursive` over its variants (`Const`, `Ref`, `Not`, `And`, `Or`, `Cmp`, `Arith`, `Count`, `SetOp`, `Contains` — read the exact fields from `src/core/features.rs` lines ~210-330 at implementation time), depth ≤ 4; `HeuristicStrategy` arbitrary = `HeuristicStrategy::new(name)` + arbitrary `Rule`s (`Rule::new(name, priority, condition, ActionSelector)`) — round trip only, validity not required; `StrategySpec` arbitrary over `Random`, `Minimax { depth 1..=9, epsilon 0.0..=1.0, tie_break }`, `HeuristicRules { heuristic }`. Round trip = JSON `to_string` → `from_str` → `assert_eq!`, plus TOML for `StrategySpec`.
- The three serde round-trip properties are bit-exact over `FeatureValue::Float(f64)` (and `epsilon: f64`): they require serde_json's `float_roundtrip` feature (Constraints `Cargo.toml` bullet; ADR 0013). Without it `serde_json::from_str` is one ULP off for ~10.4% of f64 values (e.g. `Float(-261601.74642673362)` reads back as `Float(-261601.7464267336)`). Never relax the generators, the `assert_eq!`, or the test names to tolerate ULP differences — the feature is what makes the property honest.
- `ProptestConfig { cases: 256 (state invariants) / 64 (serde), .. }` keeps the file under ~3 s in debug. No `proptest-regressions` file is expected; if one appears from a real failure, commit it.

## Assumptions

- `proptest` (1.x), `tempfile` (3.x), `assert_cmd` (2.x) resolve and build on stable 1.94.1 with edition 2024 and are fetchable (network available to the worker that adds them; later workers reuse the registry cache).
- `game-player` stays pinned; no engine API change is needed — the harness composes `RayonMatchEngine`, `StrategyRegistry`, `MinimaxProvider`, `RandomProvider` as `play` does.
- `serde_json::to_value` of every `G::Action` is deterministic (no `preserve_order`; sorted object keys are stable), so `BehaviorSignature.actions: Vec<serde_json::Value>` is byte-stable.
- serde_json's `float_roundtrip` feature changes only the f64 PARSER (exact read-back at a parse-speed cost), never the writer: every existing persisted output, pinned run_id and byte-identity artifact is unaffected, and the debug `cargo test --workspace` budgets hold (the suite parses a few thousand floats at most).
- Depth-9 minimax with `SeededUniform` tie-break always chooses an optimal action, so its agreement against the exhaustive annotation is exactly 1.000 (already true for the corpus-side `agreement` analyzer: `perfect` rate 1.0).
